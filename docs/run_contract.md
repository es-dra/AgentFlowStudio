# Workflow Run Contract

Phase 7.5 standardizes workflow run outputs so a NarratoCut run can be inspected,
evaluated, replayed, and read by future agent tooling without giving an agent
control of the workflow.

The default workflow remains local and mock-driven:

```text
text -> hooks -> scripts -> clip_plans -> mock clips
```

No run contract artifact requires FFmpeg, network access, API keys, a database,
a queue, or an agent runtime.

Phase 9 adds a separate `real_video` workflow mode. It does not change the
default mock pipeline. Real-video runs write `workflow_mode` and
`quality_profile` explicitly in `run_manifest.json` so inspection does not infer
behavior from incomplete artifacts.

## Run Directory

A full mock workflow run writes:

```text
data/processed/runs/demo_full_mock/
+-- clips/
+-- hooks.json
+-- scripts.json
+-- clip_plans.json
+-- slice_manifest.json
+-- manifest.json
+-- run_manifest.json
+-- trace.json
+-- quality_report.json
```

`manifest.json` is the legacy workflow manifest. It remains available for
backward compatibility. New automation should prefer `run_manifest.json`,
`trace.json`, and `quality_report.json`.

## `run_manifest.json`

`run_manifest.json` describes what this run is, where it came from, and what
artifacts it produced.

Key fields:

- `project`: always `NarratoCut`
- `run_id`: run directory identity
- `workflow`: workflow YAML path or workflow name
- `mode`: currently `mock`
- `workflow_mode`: execution semantics such as `mock` or `real_video`
- `quality_profile`: inspection profile such as `mock` or `real_video`
- `created_at`: ISO timestamp from the workflow run
- `status`: `success` or `failed`
- `inputs`: normalized input references, such as `text`
- `artifacts`: run artifacts, including `manifest` and `clips_dir`
- `environment`: whether FFmpeg or network access was required

Example:

```json
{
  "project": "NarratoCut",
  "run_id": "demo_full_mock",
  "workflow": "workflows/mock_text_to_slices.yaml",
  "mode": "mock",
  "created_at": "2026-05-17T01:30:00+08:00",
  "status": "success",
  "inputs": {
    "text": "examples/demo_text/story.txt"
  },
  "artifacts": {
    "hooks": "hooks.json",
    "scripts": "scripts.json",
    "clip_plans": "clip_plans.json",
    "slice_manifest": "slice_manifest.json",
    "clips": "clips",
    "manifest": "manifest.json",
    "clips_dir": "clips/"
  },
  "environment": {
    "ffmpeg_required": false,
    "network_required": false
  }
}
```

## `trace.json`

`trace.json` records workflow step execution without putting trace logic inside
business nodes.

Each step includes:

- `step_id`
- `status`
- `started_at`
- `ended_at`
- `duration_ms`
- `inputs`
- `outputs`
- `warnings`
- `errors`

The workflow runner owns this artifact because step timing belongs to runtime
execution, not to individual node implementation.

## `quality_report.json`

`quality_report.json` is generated by the harness inspection layer. It checks
whether expected run artifacts exist and whether basic mock pipeline structure is
reasonable.

Current checks include:

- hooks file exists and is non-empty
- scripts file exists and is non-empty
- clip plans file exists and is non-empty
- legacy `manifest.json` exists
- `run_manifest.json` exists
- `trace.json` exists
- `slice_manifest.json` exists
- `clips/` exists
- mock clip count matches the slice manifest

The harness owns this artifact because quality checks are gates over completed
artifacts, not workflow execution order.

## CLI

Run the mock workflow:

```powershell
.venv\Scripts\ncut run-workflow --workflow workflows/mock_text_to_slices.yaml --input examples/demo_text/story.txt --output data/processed/runs/demo_full_mock
```

Inspect a run:

```powershell
.venv\Scripts\ncut inspect-run --run-dir data/processed/runs/demo_full_mock
```

Expected output shape:

```text
Run: demo_full_mock
Workflow: workflows/mock_text_to_slices.yaml
Status: pass

Artifacts:
  hooks.json               found
  scripts.json             found
  clip_plans.json          found
  slice_manifest.json      found
  manifest.json            found
  run_manifest.json        found
  trace.json               found
  clips/                   found

Quality:
  12 passed
  0 failed
  0 warnings
```

`inspect-run` exits with code 1 when the quality report status is not `pass`.

## Real Video Run Directory

A Phase 9 real-video workflow writes:

```text
data/processed/runs/demo_real_video/
+-- clips/
+-- roi_config.json
+-- clip_plan.json
+-- video_metadata.json
+-- clip_plan_validation.json
+-- real_slice_manifest.json
+-- manifest.json
+-- run_manifest.json
+-- trace.json
```

Inspection and review remain separate:

```text
run-workflow -> inspect-run -> review-run
```

`run-workflow` does not write `quality_report.json`.
