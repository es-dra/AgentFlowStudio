# AFS 全界面视觉套件复核 v0.2

状态：设计评审候选，不是实现验收  
日期：2026-07-29  
事实基准：`AFS_UI_CANONICAL_FIXTURE_V0.2.json`  
界面章程：`AFS_PRODUCT_UI_CHARTER_V0.2.zh-CN.md`

## 1. 结论

本套件已经把 AFS 从“每张图各自成立的概念界面”推进到“同一产品壳下、按专业任务拆分的完整界面体系”。

已经成立的部分：

- 全局层、项目层、制作层、运营层和管理层的边界清楚。
- 制作画布、剧本、分镜、资产设定、生成审核和合成交付不再互相吞并。
- 每个界面都有一个主要问题和一个主动作。
- 智能工作区从常驻宽聊天栏改为默认收起的窄轨，仅在有上下文时展开。
- 候选、当前查看、已采用、已交付不再使用同一视觉语义。
- 局部返工先展示范围、影响、费用和恢复策略，再允许执行。
- 制作任务、费用、权限、系统管理进入专门界面，不污染创作工作面。
- 冲突、恢复、长任务和阻塞不再只靠 Toast 或技术错误表达。

仍未达到代码实施门的部分：

- 图像生成稿中仍有少量文字和事实漂移，不能把 PNG 中的文字当作实现数据源。
- 尚未经过用户视觉方向确认。
- 尚未建立可交互原型、浏览器响应式 QA 和独立 evaluator 结论。

因此当前判定为：

```text
产品信息架构：通过
界面职责拆分：通过
视觉方向：待用户确认
跨屏事实：以 fixture 为准，PNG 需在实现前校正
代码实施：暂缓
```

## 2. 角色复核

### 创作者

通过。

- 可以从项目页直接知道继续哪个项目。
- 可以从项目概览知道下一步，而不必理解任务编排。
- 创建项目按步骤进行，不要求一次理解全部能力。
- 页面主动作使用“继续制作、更新分镜、确认采用、开始局部返工”等结果语言。

仍需验证：

- 首次使用者能否在 5 分钟内完成“导入剧本 → 查看场景 → 进入分镜”。
- 智能工作区的建议是否足够有用，而不是新的干扰源。

### 编剧与导演

通过。

- 剧本工作面以可读写正文为中心，属性不压过正文。
- 分镜工作面以构图、顺序、时长和场景节奏为中心。
- 制作画布只表达生产关系和下一步，不替代剧本或分镜工具。
- 镜头时长必须由同一事实基准投影，不能在不同页面重新计算。

仍需验证：

- 剧本格式、快捷键、块级编辑和修订历史。
- 分镜拖动、连续播放、键盘操作和大项目虚拟化。

### 制片与项目负责人

通过。

- 项目概览只呈现进度、阻塞、当前成片和最近决定。
- 任务中心解释任务能否离开页面、能否恢复和结果去向。
- 费用页解释预算、预留、预计成本和确认规则。
- 团队页用自然语言说明关键权限。
- 合成交付明确区分“可播放”“尚未就绪”和“可导出”。

仍需验证：

- 费用归集、预留释放、失败任务计费和退款口径。
- 交付检查的证据来源及版本冻结规则。

### 产品设计

方向通过，像素级实施基准待校正。

- 统一壳层成立，但各工作面没有被做成同一模板。
- 颜色、圆角、分隔线、密度和主动作层级基本统一。
- 大部分页面保持两至三个主要区域。
- 没有使用渐变、发光、玻璃拟态和大卡片海洋。

必须修正：

- 图像生成的中文小字偶有错字。
- 个别图片中的选中对勾可能与“已确认/已采用”混淆。
- 个别背景数据与 fixture 不一致。
- 小字号和弱对比在实现时必须重新测量，不能照抄像素图。

### 前端工程

结构通过。

- `AppShell` 只实现一次。
- 六个制作工作面按路由拆包。
- 全局界面不加载项目媒体和 ProductionGraph 全量数据。
- 智能工作区是共享容器，建议、任务和会话由上下文适配器提供。
- 所有长列表、素材网格和时间线都有虚拟化边界。

实施要求：

- React + TypeScript 使用领域类型，禁止用散落字符串模拟状态。
- 页面只消费面向界面的读模型，不直接拼装内部运行时对象。
- 采用、返工、交付使用 preview/confirm。
- 所有可变更按钮由服务端 `allowed_actions` 约束。

### 后端与数据

契约方向通过。

- 每个界面都有专用摘要，不再依赖一个万能项目详情接口。
- ProductionGraph 是项目结构、顺序、状态和影响范围的唯一权威。
- 资产、候选、采用结果、任务和交付版本必须可追溯。
- 长任务有持久状态、检查点、幂等键和结果回写。
- 采用和返工必须产生可审计决定，不直接覆盖旧结果。

实施要求：

- UI fixture 只用于设计和测试，不替代真实数据库。
- 列表接口游标分页，媒体按可见性延迟加载。
- 命令返回任务回执和服务器确认版本。
- 事件流断开后可从游标继续，不以页面轮询维持真相。

### 运维与性能

设计覆盖通过，运行证据未在本轮验证。

- 任务、恢复、备份和容量都有产品化界面。
- 普通创作界面不暴露端口、进程、路径和内部诊断。
- 管理概览只给摘要，并允许下钻证据。
- 应用健康、任务处理、媒体存储、数据库和备份不能互相替代。

实施要求：

- 首屏只加载壳层、项目摘要和当前工作面。
- 媒体支持 Range，请求可取消，相同对象合并读取。
- 500 镜头和 5,000 资产下保持可操作。
- 非 Provider 读接口目标 `p95 <= 250ms`。

### 安全、权限与无障碍

方向通过。

- 普通界面不出现 secret、签名链接、绝对路径和 Provider 原始输出。
- 权限以业务动作表达，同时保留服务端强制校验。
- 高风险动作不直接放在概览或主路径。
- 状态同时使用文字、图标和颜色。

实施要求：

- WCAG AA 对比度。
- 全流程键盘可达，拖拽必须有非拖拽替代。
- 视频、时间线、候选比较和对话框有明确焦点顺序。
- 冲突、失败、恢复和任务完成使用可控状态播报。

## 5. 进入实现前的硬门

```text
用户确认这一套视觉方向
  -> 用 fixture 逐屏校正文案和数字
  -> 锁定组件 token 与图标语义
  -> 锁定页面读模型和 preview/confirm 命令
  -> 建立 React + TypeScript 产品壳
  -> 先实现 V01、V03、V04、V08、V09、V10 垂直切片
  -> 浏览器交互、状态、响应式和无障碍 QA
  -> 独立 evaluator
  -> 再迁移其余界面
```

在用户确认视觉方向前，不把这些 PNG 当作已批准实现，也不开始产品代码迁移。
