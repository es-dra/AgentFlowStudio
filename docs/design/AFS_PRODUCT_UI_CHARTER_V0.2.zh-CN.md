# AFS 产品界面章程 v0.2

状态：统一视觉套件与 React + TypeScript 实施前的强约束基线
日期：2026-07-29
主要用户：中文内容创作者、导演、制片人、剪辑师、审核者和团队管理员
适用范围：账户入口、项目、六个制作工作面、素材库、任务、团队、模型费用和系统管理

## 1. 章程目标

本章程解决的不是“界面是否好看”，而是 AFS 能否成为一套长期可用、功能不漂移、状态可信、能完成作品的商业级内容生产系统。

界面设计必须同时实现：

1. 用户始终知道自己在哪个项目、哪个工作面、正在处理哪个对象。
2. 同一场次、镜头、资产、候选、任务和交付版本在全部界面保持同一事实。
3. 每个界面只回答一个主要问题，只保留一个高权重主动作。
4. 制作画布、剧本、分镜、资产设定、生成审核和合成交付各自拥有专业工具，不相互复制。
5. 创作助手解释并推进同一条命令链，不形成第二套控制中心。
6. 影响、费用、权限、任务和恢复在高风险动作前可验证。
7. 技术标识、模型渠道、任务内部字段和诊断信息默认隐藏。
8. 页面密度服务工作，不使用卡片堆叠、装饰图形或空面板填满界面。

## 2. 权威顺序

设计与实现发生冲突时，按以下顺序处理：

```text
ProductionGraph 与服务端权威事实
  → 用户完成作品的真实工作流
  → 本章程的界面职责与状态规则
  → 统一组件和视觉系统
  → 单张视觉稿
```

单张视觉稿不能修改产品对象、时长、镜头数量、候选状态或命令语义。

所有视觉稿和原型必须使用：

```text
docs/design/AFS_UI_CANONICAL_FIXTURE_V0.2.json
```

任何数字、状态和对象引用发生矛盾，视觉稿自动判定为失败。

## 3. 十二条界面法度

### 法度 1：一个界面，一个主要问题

| 界面 | 只回答的主要问题 |
|---|---|
| 项目 | 我现在要进入哪部作品？ |
| 项目概览 | 这部作品下一步最值得处理什么？ |
| 制作画布 | 当前内容对象怎样关联，修改会影响哪里？ |
| 剧本 | 故事结构和文本是否成立？ |
| 分镜 | 镜头顺序、节奏和拍摄意图是否成立？ |
| 资产设定 | 人物、场景和道具是否一致、可复用？ |
| 生成审核 | 哪个候选可以进入作品？ |
| 合成交付 | 当前版本能否完整播放和交付？ |
| 素材库 | 哪些已确认资产可以复用？ |
| 制作任务 | 哪些任务正在执行、失败或需要恢复？ |
| 团队与权限 | 谁能查看、修改和确认什么？ |
| 模型与费用 | 当前能力、预算和费用是否受控？ |
| 系统管理 | 运行、迁移、审计和恢复是否健康？ |

### 法度 2：一个界面，一个主动作

- 主动作使用实心强调色。
- 支持动作最多两个，使用低权重按钮或文本动作。
- 页面、助手、底部栏和弹窗不得同时出现语义相同的主动作。
- 主动作不可执行时，改为明确的阻塞说明和下一步，不保留无解释的禁用按钮。

### 法度 3：常驻区域不超过三块

除全局壳外，工作面最多包含：

1. 一个局部导航；
2. 一个主工作区；
3. 一个创作助手窄栏或展开栏。

详情、来源、影响、历史和诊断使用抽屉、浮层或临时分栏，不常驻占宽。

### 法度 4：空内容不占永久空间

- 没有进行中任务时，不显示大块“暂无任务”卡。
- 没有建议时，创作助手折叠为窄栏。
- 没有阻塞项时，不保留空的阻塞面板。
- 空状态必须给出一个合理下一步，但不制造虚构数据。

### 法度 5：跨界面对象必须同形同义

每个媒体对象必须表达：

```text
对象归属
媒体类型
版本
审核状态
采用状态
来源
受影响范围
```

聚焦、选中、待审核、已采用和已冻结不得共用同一个勾、边框或颜色。

### 法度 6：同一动作只有一条命令路径

创作助手、对象操作条和详情抽屉可以发起同一个动作，但必须进入同一个命令预览：

```text
提出意图
  → 影响 / 费用 / 权限 / 保留内容预览
  → 用户确认
  → 服务端回执
  → 即时结果或持久任务
```

### 法度 7：高风险动作必须先解释

以下动作不得直接执行：

- 覆盖剧本确认版本；
- 批量调整分镜；
- 生成图片、关键画面或视频；
- 采用候选；
- 局部返工；
- 冻结交付；
- 导出或公开发布。

确认前至少说明：

```text
会改变什么
会保留什么
影响哪些对象
预计费用
需要谁确认
失败后如何恢复
```

### 法度 8：状态必须完整

每个核心界面都要设计并实现：

```text
加载中
空状态
可操作
编辑未保存
服务器已确认
内容已更新
版本冲突
离线只读
无权限
制作中
派发结果待核对
失败可恢复
恢复中
```

只画“正常完成态”不能成为实施基准。

### 法度 9：创作助手不是聊天外挂

- 默认是 48–56px 常驻窄栏。
- 有当前建议、任务或用户主动打开时扩展为 336–400px。
- 只围绕当前项目和稳定对象引用工作。
- 每次只给一个主建议和一个备选。
- 不能复制页面已有的主按钮。
- 必须显示建议基于哪个对象状态；过期后立即标记失效。

### 法度 10：纯中文但不文档化

- 使用短、自然、可行动的中文。
- 不把设计文档、系统解释或内部字段直接搬进界面。
- 按钮使用动词和结果，如“继续审核”“预览影响”“确认采用”。
- 错误首先说明保留了什么和怎样继续，再提供诊断入口。

### 法度 11：专业能力按工作面就近出现

- 剧本工具不进入制作画布。
- 分镜节奏工具不进入资产设定。
- 候选比较不进入项目概览。
- 时间线装配不进入生成审核。
- 管理诊断不进入创作者工作区。

### 法度 12：视觉一致不等于每页相同

全局壳、字体、颜色、间距、图标、状态和按钮语法保持一致；各工作面根据任务使用不同内容结构和密度。

## 4. 统一产品壳

### 4.1 桌面结构

```text
┌──────────────────────────── 全局栏 52 ────────────────────────────┐
│ AFS｜项目切换｜最后检查点｜撤销/恢复                  播放｜交付｜账户 │
├──────┬──────────────────── 工作面导航 44 ────────────────┬───────┤
│ 全局 │ 制作画布｜剧本｜分镜｜资产设定｜生成审核｜合成交付 │ 助手窄栏 │
│ 导航 │──────────────────────────────────────────────────│ 48–56 │
│ 52   │                                                  │       │
│      │                 当前工作面                       │       │
│      │                                                  │       │
└──────┴──────────────────────────────────────────────────┴───────┘
```

助手展开时覆盖或挤压主区的策略由视口决定；不得在 1440px 下同时常驻全局宽栏、局部宽栏、详情宽栏和助手宽栏。

### 4.2 全局栏

只允许：

- AFS 品牌标记；
- 项目切换；
- 最后检查点与恢复状态；
- 撤销 / 恢复；
- 播放；
- 交付；
- 账户。

禁止：

- 技术版本号；
- Provider 状态；
- 内部任务号；
- 多个指标；
- 搜索、通知、帮助、设置全部堆进同一行。

低频入口放入账户或全局菜单。

### 4.3 全局导航

桌面以 52px 图标栏存在，悬停、聚焦或展开后显示中文：

```text
项目
素材库
制作任务
团队
设置
```

进入制作工作面后仍保持相同位置，不消失、不变形。

### 4.4 工作面导航

固定顺序：

```text
制作画布
剧本
分镜
资产设定
生成审核
合成交付
```

- 不使用胶囊标签。
- 当前工作面使用 2px 强调线和加深文字。
- 有待决策或阻塞时使用小型语义点与可访问文本，不显示数字海洋。
- 工作面导航不承担项目进度条职责。

### 4.5 统一对象头

需要处理具体对象的界面在内容区顶部共享：

```text
项目 > 集次 > 场次 > 当前对象
对象类型与状态
最后确认时间
下游影响摘要
唯一主动作
```

技术版本和精确引用进入“制作详情”。

## 5. 视觉与组件系统

### 5.1 颜色

```text
应用底色          #0E1114
一级工作面        #13171B
二级工作面        #181D22
悬浮与输入        #20262C
主要文字          #F2F4F5
次要文字          #B4BBC1
辅助文字          #858E96
分隔线            #2B3238
品牌强调          #20A99A
完成              #4FB477
提醒              #E5A84B
错误              #E16666
```

- 不使用蓝紫渐变、霓虹、玻璃拟态和大面积辉光。
- 强调色只表示当前选择和主动作。
- 状态必须同时使用文字或图标，不只靠颜色。
- 长文本编辑可以使用同一系统的浅色“阅读纸面”，但全局壳不变，且用户可切换深色编辑面。

### 5.2 字体

```text
界面字体：PingFang SC / Microsoft YaHei / Noto Sans CJK SC
数字辅助：与界面字体一致，不引入独立装饰字体
工作面标题：20–22px / 600
对象标题：16–18px / 600
正文：14px / 400
控件：13–14px / 500
辅助：12px / 400
```

正文小于 13px、辅助文字小于 12px、依赖细灰字传达关键状态均为失败。

### 5.3 间距与形状

```text
间距：4 / 8 / 12 / 16 / 24 / 32
控件高度：32 / 36 / 40
基础圆角：6
媒体圆角：8
抽屉和菜单圆角：8
```

- 不使用大胶囊按钮。
- 不使用卡片套卡片。
- 列表优先使用行分隔，不把每行做成独立卡片。
- 同一屏幕最多一种明显阴影。

### 5.4 图标

- 使用同一套 1.5–1.75px 线性图标。
- 导航、状态、工具和媒体控制使用不同语义集合，但风格一致。
- 不用 emoji、字符箭头和近似图标。
- 每个纯图标按钮必须有中文可访问名称和工具提示。

### 5.5 密度等级

| 等级 | 使用界面 | 原则 |
|---|---|---|
| 舒展 | 登录、新建项目 | 强引导、少字段 |
| 标准 | 项目、项目概览、团队、费用 | 列表与摘要平衡 |
| 专业 | 制作画布、剧本、分镜、资产设定 | 高信息密度但层级清楚 |
| 审片 | 生成审核、合成交付 | 媒体最大化，界面退后 |
| 运维 | 制作任务、系统管理 | 表格、状态和恢复动作优先 |

## 6. 全量界面登记

### A01 登录

- 路由：`/login`
- 主要问题：怎样安全进入我的工作空间？
- 主动作：`继续登录`
- 区域：品牌与产品说明、登录表单、异常恢复。
- 关键功能：登录、会话过期说明、账户恢复、隐私与服务入口。
- 状态：初始、提交中、验证失败、账户受限、会话恢复。
- 后端：认证挑战、会话、组织列表。
- 禁止：作品案例轮播、功能卡片、营销指标、模型宣传。

### P01 项目

- 路由：`/projects`
- 主要问题：我现在要进入哪部作品？
- 主动作：`新建项目`
- 区域：项目列表、最近活动与恢复提示；不显示创作助手。
- 关键功能：搜索、最近项目、归档项目、恢复到上次位置、导入。
- 默认结构：表格或紧凑列表，可切换缩略图视图。
- 状态：加载、空列表、搜索为空、只读项目、恢复可用、项目异常。
- 后端：项目摘要聚合，不在读取时写资产索引。
- 禁止：项目卡片海、虚构统计、将所有项目阶段塞进一张卡。

### P02 新建项目

- 路由：`/projects/new`
- 主要问题：怎样建立足够但不过量的作品上下文？
- 主动作：最后一步为 `创建项目`
- 结构：四步向导。

```text
作品信息
  → 目标规格
  → 导入剧本或从空白开始
  → 检查并创建
```

- 每步最多五个核心字段。
- 高级模型、预算、团队和存储配置放入创建后设置。
- 状态：保存草稿、导入解析、字段错误、名称冲突、创建恢复。
- 禁止：把所有项目配置放在一张长表单。

### S00 项目概览

- 路由：`/studio/?surface=overview`
- 主要问题：下一步最值得处理什么？
- 主动作：`继续审核镜头 03`
- 区域：
  1. 当前待决策；
  2. 生产覆盖与阻塞；
  3. 最近变化。
- 使用“覆盖、受阻、在途、可交付”表达项目状态，不使用线性瀑布步骤条。
- “最近变化”必须显示对象身份、变更类型和时间，不只展示图片。
- 创作助手默认窄栏；只有建议与当前待决策直接相关时展开。
- 后端：`resume_target`、决策队列、任务摘要、恢复摘要、交付摘要。
- 禁止：营销式巨幅背景图、阶段流水线、空任务卡。

### S01 制作画布

- 路由：`/studio/?surface=canvas`
- 主要问题：对象怎样关联，改动会影响哪里？
- 主动作：根据当前对象显示 `预览影响` 或 `发起制作`
- 区域：场次定位、制作脉络、助手窄栏。
- 关键功能：
  - 缩放、平移、框选、定位；
  - 场次、镜头、资产和候选关系；
  - 影响范围高亮；
  - 对象附近的上下文操作条；
  - 来源与影响抽屉。
- 节点只显示名称、类型、缩略图、状态和一个动作。
- Graph 布局在 Worker 或服务端计算。
- 禁止：把剧本编辑、候选审核、参数表和交付时间线全部放进节点。

### S02 剧本

- 路由：`/studio/?surface=script`
- 主要问题：故事结构和文本是否成立？
- 主动作：`预览结构影响`
- 区域：场次目录、结构化编辑器、助手窄栏。
- 关键功能：
  - 场次、动作、对白和角色结构；
  - 查找与跳转；
  - 版本比较；
  - 未保存修改；
  - 结构确认前的受影响镜头预览。
- 长文本保持 55–65 个中文字符的舒适行宽。
- 禁止：模型参数、生成队列、资产候选和审片播放器常驻。

### S03 分镜

- 路由：`/studio/?surface=storyboard`
- 主要问题：镜头顺序、节奏和拍摄意图是否成立？
- 主动作：`预览本场节奏`
- 区域：场次栏、连续镜头序列与选中镜头详情、助手窄栏。
- 关键功能：
  - 镜头重排；
  - 拆分、合并；
  - 连续播放；
  - 时长自动对账；
  - 剧本节拍映射；
  - 景别、运动、声音、转场；
  - 参考资产稳定引用；
  - 多选批量调整。
- 当前样例固定为 3 场、7 镜、77 秒；第二场 28 秒由镜头 03/04/05 的 8/11/9 秒组成。
- 禁止：静态图片网格、各页面自行计算时长、将所有技术提示词铺在卡片上。

### S04 资产设定

- 路由：`/studio/?surface=asset-bible`
- 主要问题：资产身份是否一致、完整、可复用？
- 主动作：随当前状态显示 `确认资产设定` 或 `审核候选`
- 区域：类型与状态筛选、资产列表、选中资产详情。
- 使用主从列表，不默认使用大卡片网格。
- 关键功能：
  - 人物、场景、道具和风格；
  - 身份描述、别名、关键特征；
  - 当前采用媒体；
  - 媒体候选；
  - 引用场次和镜头；
  - 合并、退役和替换影响。
- 资产身份、候选媒体和采用版本必须分层。
- 禁止：把一张图片同时当作资产身份、候选和采用结果。

### S05 生成审核

- 路由：`/studio/?surface=review`
- 主要问题：哪个候选可以进入作品？
- 主动作：`确认采用`
- 区域：审核队列、大媒体审片区、助手窄栏。
- 关键功能：
  - 待审核、需处理、已采用队列；
  - 当前候选、上一版和其他候选；
  - 播放、逐帧、循环区间；
  - 并排、擦除和快速切换比较；
  - 时间点问题和区间标记；
  - 对当前媒体适用的质量检查；
  - 来源、影响和采用回执。
- 聚焦候选使用细边框；已采用使用明确文字与独立状态图标。
- 禁止：未采用候选使用完成勾、通用质量模板、重复返工按钮。

### S06 局部返工预览

- 形态：生成审核或合成交付中的抽屉 / 全高临时面板，不是独立常驻路由。
- 主要问题：这次返工会改变什么、保留什么、花费多少？
- 主动作：`确认局部返工`
- 必须显示：
  - 问题时间区间；
  - 将保留的媒体与输入；
  - 将替换的候选；
  - 受影响镜头和交付片段；
  - 费用、权限和检查条件；
  - 任务失败后的回退版本。
- 确认后关闭预览，返回原审核位置，并在任务窄条显示进度。
- 禁止：直接从一句助手建议派发 Provider。

### S07 合成交付

- 路由：`/studio/?surface=delivery`
- 主要问题：当前版本能否完整播放和交付？
- 主动作：阻塞清零后为 `创建交付版本`
- 区域：交付版本与阻塞、播放器和装配时间线、助手窄栏。
- 关键功能：
  - 当前装配版本；
  - 镜头、对白、音乐和字幕时间线；
  - 真实完整播放；
  - 缺失、未采用和质量阻塞；
  - 输出规格；
  - 冻结、导出和版本历史；
  - 从交付片段反查镜头与候选。
- 每次导出创建不可变版本，不覆盖上一版本。
- 禁止：尚有阻塞时突出导出按钮、把交付做成几个下载卡片。

### G01 素材库

- 路由：`/library`
- 主要问题：哪些已确认资产可以复用？
- 主动作：`引用到项目`
- 区域：筛选、素材列表、详情预览。
- 关键功能：组织范围、类型、使用权、来源项目、采用版本、引用次数、退役状态。
- 引用到项目后仍由 ProductionGraph 记录关系，不复制第二份资产真相。
- 禁止：未经确认的候选进入公共素材库。

### G02 制作任务

- 路由：`/tasks`
- 主要问题：哪些任务正在执行、失败或需要恢复？
- 主动作：随选中任务显示 `继续核对`、`恢复任务` 或 `取消任务`
- 默认使用表格或分组列表。
- 关键功能：
  - 任务类型和对象；
  - 排队、执行、待核对、失败和完成；
  - 进度和开始时间；
  - 可取消条件；
  - 重试与 Provider 派发核对；
  - 恢复回原工作面。
- 禁止：把任务中心做成技术日志查看器。

### G03 团队与权限

- 路由：`/settings/team`
- 主要问题：谁能查看、修改和确认什么？
- 主动作：`邀请成员`
- 区域：成员列表、角色与项目权限、决策记录入口。
- 关键功能：成员、团队、角色、项目授权、显式拒绝、待邀请、最近关键决策。
- Creator 工作面只显示必要责任和权限；完整矩阵在此管理。
- 禁止：在此暴露 Provider secret 或运行诊断。

### G04 模型与费用

- 路由：`/settings/models-and-cost`
- 主要问题：能力、预算和费用是否受控？
- 主动作：`保存预算设置`
- 区域：预算摘要、能力路由、费用记录。
- 关键功能：
  - 图片、视频、文本等能力是否可用；
  - 项目和组织预算；
  - 已用、预留和待核对费用；
  - 路由优先级；
  - 数据和隐私要求；
  - 账户健康摘要。
- secret 只显示“已配置/未配置”，不能返回值。
- 禁止：让创作者在每次生成时理解 Provider 技术细节。

### G05 账户与偏好

- 路由：`/settings/account`
- 主要问题：怎样管理我的账户和工作偏好？
- 主动作：`保存设置`
- 关键功能：个人信息、通知、语言固定为中文、主题、快捷键、默认布局、会话安全。
- 禁止：将项目业务配置混入个人偏好。

### M01 系统管理

- 路由：`/admin`
- 主要问题：运行、迁移、审计和恢复是否健康？
- 主动作：根据上下文显示 `查看处置方案`，危险操作另行确认。
- 区域：健康摘要、异常与恢复、审计与迁移。
- 关键功能：
  - API、Worker、数据库、对象存储；
  - 队列和发件箱延迟；
  - Provider 账户健康但不显示 secret；
  - 迁移状态；
  - 安全事件；
  - 备份与恢复证据。
- 与 Creator Studio 使用同一品牌系统，但信息密度和权限独立。
- 禁止：把系统管理入口放进普通创作者工作面主导航。

## 7. 创作助手合同

### 7.1 固定结构

展开时最多五段：

```text
当前对象
为什么现在处理
一个主建议和一个备选
影响 / 费用 / 保留内容
任务回执或输入区
```

### 7.2 行为

- 工作面切换不卸载会话。
- 对象切换更新上下文，但保留可回看对话。
- 建议绑定 `based_on_project_version` 和精确对象引用。
- 项目版本变化时，建议显示“内容已更新，需要重新检查”。
- 没有建议时折叠，不显示空面板。
- 任务进入后台后，助手显示轻量回执并把完整状态交给制作任务中心。

### 7.3 禁止

- 不复制页面主按钮。
- 不直接写 Graph、数据库或对象存储。
- 不展示原始 Provider 响应、secret、绝对路径或内部任务字段。
- 不用“我已经帮你完成”替代可验证回执。

## 8. 状态矩阵

| 状态 | 壳层表达 | 内容区表达 | 可用动作 |
|---|---|---|---|
| 加载中 | 保留稳定壳 | 与最终结构一致的骨架 | 取消过期请求 |
| 空状态 | 正常 | 说明为什么为空 | 一个创建或导入动作 |
| 编辑未保存 | “未保存修改” | 修改位置明确 | 保存、撤销 |
| 服务器已确认 | “已保存至 14:32 检查点” | 不打扰 | 查看检查点 |
| 内容已更新 | 提醒 | 标出变化范围 | 重新载入、比较 |
| 版本冲突 | 警告 | 保留本地草稿 | 比较并解决 |
| 离线只读 | 明确只读 | 内容仍可浏览 | 重新连接 |
| 无权限 | 正常 | 说明所需权限 | 请求权限 |
| 制作中 | 任务点 | 当前对象有轻量进度 | 查看任务、按条件取消 |
| 派发待核对 | 高风险提醒 | 不允许再次付费派发 | 核对状态 |
| 失败可恢复 | 提醒 | 说明已保留内容 | 恢复、调整后重试 |
| 恢复中 | 任务点 | 展示恢复来源 | 查看恢复详情 |

## 11. 性能法度

1. 首次进入只加载壳、当前项目摘要和当前工作面。
2. 工作面按路由拆包，预取只发生在用户即将切换时。
3. 500 镜头、1000 资产和大审核队列使用虚拟列表。
4. 只加载可见缩略图；原始媒体在用户播放或放大时请求。
5. 视频使用 Range；切换工作面不重建仍在播放的媒体。
6. Graph 布局和大规模影响计算不阻塞主线程。
7. 长任务通过可续接事件流更新，不依赖页面生命周期轮询。
8. 页面切换取消过期请求；相同对象合并在途读取。
9. 非 Provider 读 API 目标 `p95 ≤ 250ms`。
10. 命令预览和确认目标 `p95 ≤ 500ms`。
11. 壳层交互目标 60fps；拖拽和时间线不得因助手更新掉帧。
12. 不以客户端缓存替代业务权威；缓存只服务速度和只读恢复。

## 12. 无障碍法度

1. 正文与控件达到 WCAG AA 对比度。
2. 所有状态同时使用文字或图标，不只使用颜色。
3. 主要操作目标至少满足 24×24 CSS px；高频或高风险动作优先 40–44px。
4. 全流程可使用键盘完成。
5. 横向镜头序列、候选比较和时间线提供非拖拽操作。
6. 局部更新、工作面切换和助手展开不丢失焦点。
7. 任务完成、失败、冲突和恢复使用可控制的状态播报。
8. 支持 200% 缩放和 320 CSS px 宽度，无关键内容丢失。
9. 视频提供字幕、文字说明和键盘播放控制。
10. 尊重 `prefers-reduced-motion`。

## 13. 响应式

### ≥1200px

- 完整全局栏、全局窄栏、工作面导航。
- 助手默认窄栏，可展开至 336–400px。
- 局部导航按工作面需要出现。

### 761–1199px

- 全局导航折叠进应用菜单。
- 助手作为可固定的右侧层，不永久挤压媒体。
- 详情使用底部抽屉。

### ≤760px

- 工作面导航横向滚动并提供“更多”。
- 助手改为底部工作区，保持会话和当前对象。
- 制作画布允许浏览和轻量决策；复杂连线编辑提示使用桌面。
- 分镜、审核和任务保留核心操作，不做另一套移动产品。

## 15. 设计评审门

### 单界面门

- 当前主要问题是否一眼明确？
- 是否只有一个主动作？
- 是否出现无关模块或空占位？
- 是否能区分对象、候选、采用和交付？
- 是否覆盖所需状态？
- 是否存在过度小字、弱对比或颜色依赖？

### 跨界面门

- 项目、场次、镜头数量和时长是否一致？
- 当前对象和任务是否连续？
- 壳层和助手是否保持？
- 相同状态和动作是否同形同义？
- 是否能从结果回到来源和影响？
- 是否能从任务回到原工作位置？

### 全栈门

- 所有数字和 allowed actions 是否来自服务器投影？
- 采用、返工和交付是否使用 preview/confirm？
- 是否存在稳定引用和项目版本？
- 是否可恢复、可审计、可幂等？
- 媒体、长列表和 Graph 是否满足性能策略？

### 实施门

只有在以下证据完成后才进入产品代码：

```text
全量界面视觉套件
  → 单界面审计
  → 跨界面事实审计
  → 用户视觉方向确认
  → 组件与后端契约确认
  → React + TypeScript 实施
  → 浏览器交互和响应式 QA
  → 独立 evaluator
```
