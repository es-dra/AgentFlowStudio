# 视觉资产特征卡标准模板 v0.1

中文摘要:本文是固定视觉资产(`visual_asset`)时手填特征卡的标准模板与填写规范。特征卡是隐性资产的主载体,生成时通过伴随包全文注入模型,其文本质量直接决定跨镜一致性上限。词法冲突检测的属性词表与本模板共用同一套字段,填写时优先使用词表内的标准词汇,可显著提高冲突预警的命中率。

非声明边界:本模板是填写规范,不代表 human acceptance 或 business validation;特征卡内容仅在用户确认固定后生效。

## 三层结构

| 层 | 字段 | 去向 | 要求 |
|---|---|---|---|
| 签名层 | `signature` | 优化提示词(用户可见) | 一句话,≤50 字,只写最具辨识度的 2-4 个特征 |
| 全卡层 | `feature_card` | 生成伴随包(用户不可见) | 结构化键值,逐项填写,详尽但不堆砌 |
| 锁定层 | `negative_locks` | 伴随包 + QA 比对基准 | 每条一个"不许变"的事实,使用词表标准词汇 |

## 人物资产(character)字段

`feature_card` 建议键(按重要度排序,至少填 1 项,推荐填全):

| 键 | 说明 | 示例 |
|---|---|---|
| `identity` | 一句话身份定位 | `28 岁左右的女性私家侦探,神情冷静` |
| `hair` | 发色+发长+发型,用词表词汇 | `黑色短发,微卷,右侧别一枚银色发夹` |
| `face` | 脸型、五官特点、显著标记 | `瓜子脸,左眉尾一道细疤,黑色眼睛` |
| `build` | 体态身形 | `身形瘦削,约 170cm` |
| `wardrobe` | 标志性服装,颜色+款式 | `红色及膝风衣,内搭黑色高领毛衣,黑色长靴` |
| `palette` | 人物专属配色 | `红黑为主,银色点缀` |
| `demeanor` | 气质与典型神态(影响表演) | `寡言,惯于侧目观察,嘴角微抿` |

`negative_locks` 示例(每条独立、可被单独临时解除):

```text
保持黑色短发
保持左眉尾疤痕
保持红色风衣
不改变身高体型比例
```

## 场景资产(scene)字段

| 键 | 说明 | 示例 |
|---|---|---|
| `location` | 空间定位 | `城市边缘的废弃天文观测站内部` |
| `layout` | 空间结构与方位关系(连续性关键) | `入口在东侧,中央是锈蚀的望远镜基座,西墙整面碎玻璃窗` |
| `props` | 可复用关键道具 | `翻倒的金属椅,墙上褪色的星图,地面积水` |
| `lighting_mood` | 光线基调 | `冷月光从西窗斜入,地面积水反光,整体青蓝色调` |
| `palette` | 场景配色 | `青蓝+锈橙` |
| `time_weather` | 时间与天气(如固定) | `深夜,雨后` |

`negative_locks` 示例:

```text
保持望远镜基座位于画面中央区域
保持西墙碎玻璃窗
不出现现代电子设备
```

## 填写规则

1. 写事实,不写愿望:特征卡描述"是什么",不写"希望画得好看"。
2. 用词表词汇:发色/发长/服装颜色等优先使用 `apps/api/runtime_attribute_vocabulary.py` 中的标准词(黑色短发、红色风衣等),冲突预警依赖词法匹配。
3. 锁定项最小化:只锁真正不许变的;锁得越多,创作越僵硬,临时解除越频繁。
4. signature 不复制全卡:签名层是辨识用的,不是压缩版全卡。
5. 中英文均可:provider prompt 以提交语言原样注入;同一项目内保持语言一致。

## 标记类特征的防字面化规范

来源:首轮真实 A/B/C 证据(`runs/studio_asset_context_live_comparison_report_20260612_final.json`)。C 臂中 `left brow scar` 被模型过度字面化为粗黑十字状符号。结论:**裸名词会被画成符号,标记类特征必须带尺寸、质感与否定限定**。

| 特征类型 | 不要这样写 | 要这样写 |
|---|---|---|
| 疤痕 | `left brow scar` / `左眉疤` | `左眉尾一道淡色细小的自然疤痕,皮肤质感,不是妆容、纹身或符号` |
| 痣 | `mole` / `痣` | `右颧骨一颗小而淡的痣,自然皮肤细节` |
| 纹身 | `tattoo` | `左前臂一小块褪色线条纹身,不显眼` |
| 雀斑 | `freckles` | `鼻梁两侧稀疏的淡雀斑` |

通用模式:`位置 + 尺寸限定(细小/淡色/不显眼) + 质感(自然皮肤/旧痕) + 否定(不是妆容/符号/图案)`。对应的 negative_lock 同样使用完整表述,如 `保持左眉尾的淡色细小疤痕,不放大、不符号化`。

每轮 A/B/C 后,把"被遵守/被字面化/被忽略"的字段观察追加到本节,持续校准表述方式。

2026-06-12 补测观察:

- 第 2 组"人物 + 场景双资产":使用完整防字面化疤痕表述后,C 臂没有再出现首轮那种粗黑十字状符号;但眉部标记仍偏醒目,后续可继续把 `淡色`、`不显眼`、`skin texture` 放到更靠前位置。
- 第 2 组证明场景资产可只走文本通道:人物占用 MiniMax 单参考图位时,场景的观测站/望远镜/青蓝冷光仍在 C 臂生效。
- 第 3 组"锁定冲突":未解除时,发色/发型锁定压制了用户提示词中的"红色长发";本次解除对应 lock 后,输出转为红色长发。说明 negative_lock 必须写成完整动作约束,并保留 request-level temporary override。

## 与预算的关系

伴随包按字符预算注入:锁定+身份段保底 400 且永不裁剪;场景段上限 250。特征卡全卡层文本如超长,低优先键(demeanor、palette)可能被裁,核心键(hair/face/wardrobe、layout/lighting_mood)靠前书写以保留。
