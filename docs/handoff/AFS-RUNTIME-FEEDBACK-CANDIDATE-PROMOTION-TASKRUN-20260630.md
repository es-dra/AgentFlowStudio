## 中文摘要

本轮继续长周期 goal-mode，但没有执行 `master` 合并、服务器三端同步、Runtime 重启或 provider smoke。`AFS-T19 Authorized Master Merge + Three-End Sync` 仍然需要明确人类授权；在没有该授权的情况下，本轮选择继续推进一个本地 deterministic 合同切片：给上一轮新增的 Runtime `feedback_candidate` 补一个单独的人工 promotion decision harness。

上一轮 T15a 已经让 `/feedback` 事件携带 `feedback_candidate`，并明确候选反馈默认不进入上下文、不写长期记忆、不写 Company KB。本轮 T15b 的目标不是改变这个默认阻断，而是增加一个可审计的“人工决定” artifact：后续操作者可以把某条候选反馈标记为 `promote_to_context_overlay`、`reject` 或 `needs_more_evidence`。即使选择 `promote_to_context_overlay`，本轮也只写入 `context_overlay_allowed=true` 的审查结论，不真正生成 context bundle、不改 Studio 状态、不写长期记忆、不写公司知识库、不打开 provider。

工程上，本轮没有复用旧 production-memory 的 operator/acceptance feedback promotion 链路，因为那是 legacy/frozen 面，直接复用会把旧 CLI 和记忆工作流带回当前 Runtime/Studio 主线。新实现是当前 Runtime Service 的小合同：读取已有 `runtime_feedback_event` artifact，校验其中的 `feedback_candidate` 与请求中的 `candidate_id`、`project_id` 一致，然后写一个新的 `runtime_feedback_candidate_promotion_decision` artifact，并把它追加到项目 manifest 的 `feedback_refs`。这样后续全量开发可以安全地从 manifest 看到“有一条候选反馈”和“这条候选反馈是否被人工允许进入下一轮上下文”，而不会把反馈记录误认为 durable memory 或 business validation。

本轮还修正了一个真实安全字段债务：`studio_quality_feedback` 以前输出的安全键名本身包含项目 artifact 安全扫描禁止的 private-link 字面量。promotion route 读取源 feedback artifact 时会被拦截。现在改为 `no_private_external_link=true`，含义不变，但不会破坏 artifact read safety。

## Contract

New public Runtime route:

```text
POST /projects/{project_id}/feedback-candidate-promotions
```

Request fields:

- `feedback_artifact_id`
- `candidate_id`
- `decision`: `promote_to_context_overlay`, `reject`, or `needs_more_evidence`
- `rationale`
- `reviewed_at`

The route:

- reads the source artifact by `feedback_artifact_id`;
- requires the source payload to be `agentflow_runtime_feedback_event`;
- requires an embedded `agentflow_runtime_feedback_candidate`;
- verifies `candidate_id` and project ownership against the source artifact;
- rejects unsafe request payloads;
- writes `runtime_feedback_candidate_promotion_decision.json`;
- registers artifact role `runtime_feedback_candidate_promotion_decision`;
- writes an `agentflow_run_trace`;
- appends the decision artifact to project `feedback_refs`.

The decision artifact explicitly keeps:

- `context_overlay_written=false`
- `durable_memory_allowed=false`
- `writes_long_term_memory=false`
- `writes_company_kb=false`
- `provider_calls_started=false`
- `raw_provider_response_stored=false`
- `external_private_link_stored=false`
- `absolute_path_stored=false`
- `media_bytes_stored=false`
