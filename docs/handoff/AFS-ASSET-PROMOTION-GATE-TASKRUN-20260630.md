## 中文摘要

本轮任务的核心结论是：`visual-assets/promote` 已经是 Studio 面向 Runtime 的
正式固定视觉资产 promotion 合同，T12 只补上“这次固定是否来源于某个已接受的
asset-card human gate”的安全来源记录。它不是新的生成能力，也不是新的 provider
调度入口。直接人工固定资产仍然可用；当 Studio 节点上已经有最近一次
`asset_card_candidate` 的 `accepted_for_next_step` 人工 gate 记录时，Studio 会把
`source_human_gate_id` 和 `source_asset_card_candidate_id` 一起发给 Runtime。
Runtime 只保存经过清洗的安全 ID，并把它们放入 `promotion_gate`。这个字段只说明
promotion 的来源链路，不能被解释为人类创作验收、商业验证、provider smoke 或生成
媒体质量通过。

本轮刻意没有把 human gate 改成 promotion 的强制前置条件，因为那会改变现有内测
工作流：用户仍然需要能直接把人工确认过的图片固定为角色、场景或道具资产。未来如果
要要求“所有固定资产必须来自 accepted gate”，应当作为单独的产品策略任务处理，并
需要 UI、Runtime 校验、旧项目兼容和迁移说明。本轮只做最小可验证合同，把原来
“前端实际发生了 gate，但固定资产记录无法追溯 gate”的断点补上。

维护约束方面，本轮没有新增第二套 promotion route，也没有让 Studio 绕过 Runtime。
为了避免把 `fixed_asset_memory/__init__.py` 推入新的 oversized warning，清洗和公开
投影逻辑被放进同包小模块 `promotion_gate.py`。`visual-asset-panel.js` 只增加一条
import 和一条 payload spread，最终仍保持 300 行。OpenAPI 由项目 exporter 重建，
path 数保持 50，只是 `VisualAssetPromoteRequest` 多了两个可选字段。所有验证都保持
provider gate closed；没有读取或写入 secret、signed URL、本地私有素材字节、
provider raw response 或生成媒体字节。

本轮目标是在 T10 Runtime human gate contract 与 T11 Studio human gate UI hook
之后，把 accepted asset-card human gate 与 fixed visual asset promotion 之间的
最小 provenance contract 接上。目标不是强制所有资产固定都必须经过 gate，也不是打开
provider 或生成媒体。

## Current Facts

- Runtime fixed visual asset promotion already had an operator review boundary:
  `promotion_review.human_confirmed=true` and
  `claim_boundary=operator_review_record_not_human_acceptance`.
- T10 human gate decisions explicitly state `promotes_fixed_asset=false` and
  `requires_separate_promotion=true`.
- T11 Studio records human gate results only as safe node summaries in
  `node.params.humanGateDecisions`.
- Before T12, Studio could record an accepted asset-card gate and later promote
  a fixed visual asset, but the promotion record did not preserve that safe
  provenance.

## Contract Judgment

`visual-assets/promote` is already a public Runtime contract and a Studio-facing
asset promotion boundary. T12 treats human gate linkage as optional provenance:

- Direct manual promotion remains valid.
- If Studio has a latest accepted `asset_card_candidate` human gate summary, it
  sends `source_human_gate_id` and `source_asset_card_candidate_id`.
- Runtime stores only sanitized safe IDs in `promotion_gate`.
- The promotion gate does not validate creative quality, does not open provider
  gates, does not generate media, and does not write long-term memory.

Deferred policy: making accepted human gate mandatory for promotion would be a
product workflow change and should be handled by a later explicit task.
