## 0. 问题定义（评测对象是什么）

当前确定性提取对表面字符串做精确去重：`人物：陈默` 与对白行 `陈师傅` 会变成**两个** analysis asset，且 `aliases` 恒为 `[]`。
本设计要衡量的是：**系统提出的身份链接提案**，在多大程度上把应属同一人的表面形式聚到同一候选身份，同时不把不同人错误连在一起。

**明确不是评测对象：**

- 人工 `merge_alias` / asset confirm 之后的权威 Graph 状态（那是产品闭环正确性，另有 API 测试）；
- 剧本理解的全量 NER / 剧情理解；
- ScriptProfile / Beat / 间接叙事提及（另案）。

## 1. 别名评测用例清单（8 条）

### 1.1 标注约定

每条用例给出：

| 字段 | 含义 |
|---|---|
| `id` | 稳定编号 |
| `type` | 现象类型（见下表） |
| `source` | 原文片段（可直接作 extract 输入） |
| `gold_clusters` | 金标身份聚类：每个 cluster 是一组**应属同一人**的表面字符串；cluster 之间互斥 |
| `must_not_link` | 明确禁止链接的字符串对（反例约束；可与跨 cluster 重叠） |
| `expected_surface_mentions` | 期望被抽到的表面形式（用于先算抽取召回，再算链接；若某表面因规则故意不抽，在备注说明） |
| `notes` | 边界与评分说明 |

**类型标签：**

| `type` | 含义 |
|---|---|
| `aka_nickname` | 本名 + 外号 / 小名 |
| `address_shift` | 称呼随关系熟悉度变化（正式 ↔ 亲昵） |
| `surname_title` | 姓 + 职衔 / 尊称（师傅、老师等） |
| `given_vs_full` | 全名 ↔ 名 / 截短称呼 |
| `kinship_address` | 亲属称呼与本名并存（**边界类**，见 §1.3） |
| `near_homograph_negative` | 形近/同姓但**不是**同一人（反例） |
| `reuse_week_script` | 复用 week 分支剧本文本，补别名标注 |

**代词 / 指代链：** 见 §1.3——**不纳入本 v0.1 金标主集**，避免与「别名」混为一谈。

### 1.2 用例正文

#### A1 — 姓+职衔（核心正例）

- **type:** `surname_title`
- **source:**

```text
标题：夜校的灯

第一场 - 内景 - 修理铺后院 - 夜

人物：陈默

陈默蹲在桌边，把一盏旧台灯拆开。门外有人喊。

李薇
陈师傅，零件送来了。

陈默
放门口就行。
```

- **expected_surface_mentions:** `陈默`, `李薇`, `陈师傅`（按现状提取器：三者都可能成为独立候选；金标链接只管身份）
- **gold_clusters:**
  - `C1`: {`陈默`, `陈师傅`}
  - `C2`: {`李薇`}
- **must_not_link:** (`陈默`,`李薇`), (`陈师傅`,`李薇`)
- **notes:** 同场景、同姓、职衔称呼指向已出现的本名——确定性规则的**第一优先覆盖带**。

#### A2 — 本名 + 外号

- **type:** `aka_nickname`
- **source:**

```text
标题：外号

第一场

地点：校园天台
人物：周可（外号「阿可」）

周可靠着栏杆。

阿可
风有点大。

林夏
阿可，别靠那么外面。
```

- **expected_surface_mentions:** `周可`, `阿可`, `林夏`
- **gold_clusters:**
  - `C1`: {`周可`, `阿可`}
  - `C2`: {`林夏`}
- **must_not_link:** (`周可`,`林夏`), (`阿可`,`林夏`)
- **notes:** 标签行已显式给出外号关系时，确定性应能出**高置信提案**；若只靠对白「阿可」而无标签说明，置信应下降（见 §3）。

#### A3 — 称呼升级（正式 → 亲昵）

- **type:** `address_shift`
- **source:**

```text
标题：熟了以后

第一场 - 内景 - 编辑部 - 日

人物：陈默、苏晴

苏晴
陈默，这篇还要改一版。

陈默
好。

第二场 - 内景 - 编辑部走廊 - 夜

苏晴
老陈，走吧，楼下还有灯。

陈默
你先下，我锁门。
```

- **expected_surface_mentions:** `陈默`, `苏晴`, `老陈`
- **gold_clusters:**
  - `C1`: {`陈默`, `老陈`}
  - `C2`: {`苏晴`}
- **must_not_link:** (`陈默`,`苏晴`), (`老陈`,`苏晴`)
- **notes:** 「老X」模式在中文里常见，但也易与真·姓老的人名冲突；确定性只应在**同剧本已存在「X…」本名候选**时提案，禁止全局把所有「老陈」并进任意「陈*」。

#### A4 — 全名 ↔ 名（截短）

- **type:** `given_vs_full`
- **source:**

```text
标题：叫我小名也行

第一场

地点：排练厅
人物：林悦安

林悦安
今天从第二段开始。

导演
悦安，眼神再收一点。

林悦安
明白。
```

- **expected_surface_mentions:** `林悦安`, `悦安`, `导演`（`导演` 是否入人名单取决于人名过滤器；若不入候选，则不参与聚类分母）
- **gold_clusters:**
  - `C1`: {`林悦安`, `悦安`}
- **must_not_link:** （无第二人名时为空；若抽出 `导演`，则不得链入 C1）
- **notes:** 截短名 ⊆ 全名 是弱规则，假合并风险高于「姓+师傅」；提案置信应低于 A1，且需要同剧本共现证据。

#### A5 — 反例：同姓形近，不是同一人

- **type:** `near_homograph_negative`
- **source:**

```text
标题：两个陈

第一场 - 内景 - 派出所接待室 - 日

人物：陈默、陈明

陈默
我是来做笔录的。

陈明
我是来找人的。

民警
陈先生，两位先别急，一个一个说。
```

- **expected_surface_mentions:** `陈默`, `陈明`, `民警`（`陈先生`：见 notes）
- **gold_clusters:**
  - `C1`: {`陈默`}
  - `C2`: {`陈明`}
  - （可选）`C3`: {`民警`} 仅当被抽出
- **must_not_link:** (`陈默`,`陈明`) **强制**
- **关于「陈先生」:** 对两位都成立的尊称，**金标不要求**把它链到任何一人；更不允许用「陈先生」当桥把陈默与陈明合并。评测时：若系统把「陈先生」链到其中一人，记为**可容忍的不确定提案**（不计假合并）；若借此合并 C1↔C2，记为**假合并**。
- **notes:** 假合并守卫用例。任何「同姓即可链」规则必须在此失败。

#### A6 — 反例：无关职衔撞车

- **type:** `near_homograph_negative`
- **source:**

```text
标题：另一个师傅

第一场

地点：菜场口
人物：陈默、王师傅（卖鱼）

陈默
王师傅，今天的鱼还新鲜吗？

王师傅
刚到的。

远处有人喊：
陈师傅！修车的！

陈默愣了一下——那是在叫别人。
```

- **expected_surface_mentions:** `陈默`, `王师傅`；旁白里的 `陈师傅` 若被抽出则见下
- **gold_clusters:**
  - `C1`: {`陈默`}
  - `C2`: {`王师傅`}
- **must_not_link:** (`陈默`,`王师傅`), (`陈默`,`陈师傅`) **强制**（此处「陈师傅」指场外修车人，与陈默不是同一人）
- **notes:** 同姓职衔**不等于**同人；没有同场景对话指认时，不得因「陈默」存在就吸收任意「陈师傅」。若提取器根本抽不到旁白「陈师傅」，本条主要约束**错误链接**而非召回。

#### A7 — 复用 week 剧本 + 补别名层（《海边的信》片段）

- **type:** `reuse_week_script` + `surname_title`（弱）
- **素材来源:** week 分支 `docs/internal-notes/test-scripts-character-scene/02_industry_standard_letter_by_the_sea.txt`（文本为既有创作素材，可复用；**代码未合并不影响文本复用**）
- **source:** 使用该文件全文，或至少第一场（含「邮局职员老王」与对白 `老王`）。
- **expected_surface_mentions（人物）:** `苏晴`, `老王`, `林悦`（与 week README 预期一致）
- **gold_clusters（身份链接层）:**
  - `C1`: {`苏晴`}
  - `C2`: {`老王`} —— 「邮局职员老王」bio 与对白 `老王` 是**同一表面名**，属于抽取去重而非别名链接；本条金标**不要求**额外 alias 边
  - `C3`: {`林悦`}
- **must_not_link:** (`苏晴`,`老王`), (`苏晴`,`林悦`), (`老王`,`林悦`)
- **notes:** 作为**回归锚**：别名系统不得把「她的朋友林悦」拆错或与苏晴合并；也不要把「爸」（第三场自语对象）建成与苏晴的 alias。第三场「爸」属亲属称呼 / 不在场实体，见 §1.3 / §4。

#### A8 — 亲属称呼与本名（边界，记分方式特殊）

- **type:** `kinship_address`
- **素材来源:** week `03_labeled_fields_homecoming.txt` 第二场精神 + 新增强别名压力
- **source:**

```text
标题：归途（别名增补）

第一场

时间：正午
地点：老屋门口
人物：陈浩、林秀（陈浩的母亲）

林秀
浩子，你瘦了。

陈浩
妈，我回来了。
```

- **expected_surface_mentions:** `陈浩`, `林秀`, `浩子`, `妈`
- **gold_clusters（严格别名层）:**
  - `C1`: {`陈浩`, `浩子`}  —— 小名/昵称，属于别名
  - `C2`: {`林秀`}
- **must_not_link:** (`陈浩`,`林秀`), (`浩子`,`林秀`)
- **关于「妈」:** **不纳入 C2 的强制成员**。亲属称呼是**角色关系标签**，在对话里可轮转指不同人；把它当 `aliases` 等价于本名，会在多角色剧本里制造假合并。v0.1 评分：
  - 将「妈」链到林秀 → **不计正确别名加分**（可选：记 `soft_link` 观察项）；
  - 将「妈」链到陈浩 → **假合并**；
  - 不抽「妈」或不提案 → **不扣假分裂**（对亲属称呼默认豁免假分裂）。

### 1.3 代词 / 指代链：要不要纳入？

**结论：v0.1 主评测集不纳入。**

| | 别名 / 身份链接 | 代词指代（coreference） |
|---|---|---|
| 典型例子 | 陈默 ↔ 陈师傅 | 他 / 她 / 那个人 ↔ 陈默 |
| 表面形式 | 多为专名或称呼短语 | 多为封闭词类 |
| 证据 | 常有姓氏、职衔、显式 aka 标注 | 依赖篇章句法与世界知识 |
| 出错形态 | 假分裂（多人候选）/ 假合并（同姓） | 整段指代链漂 |

二者最终都服务「同一实体」，但**问题类型、特征、错误代价不同**。把代词塞进别名金标，会逼确定性规则去做它做不好的事，并污染假分裂率。

可选后续集（**不在本次设计验收内**）：`pronoun_coref_v0`，与本集指标分开报表。

## 2. 评测指标定义

### 2.1 评测层面：提案质量，不是权威事实

所有指标默认在 **proposal layer** 计算：

1. 跑确定性 extract（现状或未来实现），得到一组候选身份（每个身份有 `display_name` + 提案中的 `aliases[]` 或等价 link 提案，见 §3）；
2. 将每个身份展开为**表面字符串集合**（`display_name ∪ aliases`），得到系统聚类 \(\hat{\mathcal{C}}\)；
3. 与金标聚类 \(\mathcal{C}^*\) 比较。

**不**在「自动写入 Production Graph」后计算；人工 confirm / `merge_alias` 前后的权威状态用现有 API 测试覆盖，不计入本套 P/R 式指标。

若未来存在「链接提案」对象但尚未写入 `aliases`，则先把被提案链接的表面形式并入同一临时 cluster 再计分（仍标记为 proposal）。

### 2.2 预处理：对齐到「可评分提及」

设金标中出现的全部表面字符串集合为 \(M^*\)（所有 `gold_clusters` 的并集，**不含** §1.3 豁免项如强制忽略的「妈」——按用例 notes）。

设系统抽出的表面字符串集合为 \(M^{\mathrm{sys}}\)。

**计分宇宙（mention universe）** \(M = M^* \cap M^{\mathrm{sys}}\)。

- 金标有、系统未抽出的字符串：记入 **抽取召回缺口** \(R_{\mathrm{extract}}\)，**不计入**假分裂（避免把「没抽到」双罚成链接失败）。
- 系统抽出、金标未要求的字符串：记入 **额外候选**；若被链进某金标人且违反 `must_not_link`，计假合并；否则不惩罚聚类主指标。

每条用例先报告：`|M*|`, `|Msys|`, `|M|`，再报告链接指标。

### 2.3 身份聚类准确率（BCubed F1）

采用 **BCubed**（对聚类任务直观，且对簇大小不对称较稳），在宇宙 \(M\) 上计算。

对任意提及 \(m \in M\)：

- \(\mathrm{Gold}(m)\)：金标中与 \(m\) 同簇的提及集合（∩ \(M\)）
- \(\mathrm{Sys}(m)\)：系统中与 \(m\) 同簇的提及集合（∩ \(M\)）

\[
P_{\mathrm{BCubed}} = \frac{1}{|M|} \sum_{m \in M}
\frac{|\mathrm{Gold}(m) \cap \mathrm{Sys}(m)|}{|\mathrm{Sys}(m)|}
\]

\[
R_{\mathrm{BCubed}} = \frac{1}{|M|} \sum_{m \in M}
\frac{|\mathrm{Gold}(m) \cap \mathrm{Sys}(m)|}{|\mathrm{Gold}(m)|}
\]

\[
F1_{\mathrm{BCubed}} = \frac{2 P_{\mathrm{BCubed}} R_{\mathrm{BCubed}}}{P_{\mathrm{BCubed}} + R_{\mathrm{BCubed}}}
\quad (\text{若 } P=R=0 \text{ 则 } 0)
\]

**用例级**报告 \(F1_{\mathrm{BCubed}}\)；**集级**对用例做宏平均（每条用例权重相同），另可选微平均（按 \(|M|\) 加权）作附录。

> 不采用「系统簇数 == 金标簇数」这种粗糙准确率；也不把 ARI 作主指标（对小样本剧本方差过大）。ARI 可作附录对照。

### 2.4 假分裂率（False Split Rate）

针对金标中 **size ≥ 2** 的簇（真正存在别名的人）：

对每个金标簇 \(C^*\)（\(|C^* \cap M| \ge 2\)）：

- 令 \(C^*_M = C^* \cap M\)
- 若 \(C^*_M\) 落在系统**多于一个**簇中，则该金标人发生假分裂
- 分裂碎片数 \(k =\) 覆盖 \(C^*_M\) 的系统簇个数

**用例假分裂率：**

\[
\mathrm{FSR} = \frac{\text{发生假分裂的金标多人簇数}}{\text{金标多人簇总数（仅统计 } |C^* \cap M| \ge 2 \text{）}}
\]

另报 **分裂碎片均值** \(\overline{k}\)（仅对发生假分裂的簇），便于看「拆成 2 个还是拆成 5 个」。

现状基线预期：A1 上 \(\mathrm{FSR}=1\)（陈默 / 陈师傅 两簇）。

### 2.5 假合并率（False Merge Rate）

以 **禁止对** 为第一公民（来自 `must_not_link` 与跨金标簇对）：

令禁止对集合

\[
N = \{(a,b) \mid a \neq b,\ a,b \in M,\ a\ \text{与}\ b\ \text{不同金标簇}\}
\ \cup\ \{(a,b) \in \texttt{must\_not\_link},\ a,b \in M\}
\]

若系统把某禁止对放进同一簇，记一次假合并。

\[
\mathrm{FMR} = \frac{|\{(a,b) \in N : \mathrm{SysCluster}(a)=\mathrm{SysCluster}(b)\}|}{|N|}
\]

当 \(|N|=0\)（单人剧本）该用例 FMR 记为 `n/a`，不参与宏平均。

**硬失败规则（用例级）：** 任一 `must_not_link` 且双方 ∈ \(M\) 被合并 → 该用例标记 `HARD_FAIL`，即使 BCubed 因其它因素尚可。

### 2.6 指标怎么一起读

| 优化方向 | 健康信号 | 不健康信号 |
|---|---|---|
| 只压 FSR | 陈默/陈师傅 被并上 | A5/A6 FMR 上升、HARD_FAIL |
| 只压 FMR | 从不链接 | FSR 仍 ≈ 1，BCubed 低 |
| 目标 | FSR↓ 且 FMR≈0，BCubed↑ | 任一硬反例失败 |

**基线（当前 master，无别名智能）期望素描：**

- A1–A4、A8：高 FSR，FMR 低（因为几乎不合并）
- A5–A6：FMR 应为 0；若未来规则过猛，会先在这里爆
- A7：FSR 对多人簇不适用（各簇 size=1），主要看 FMR=0 与抽取回归

### 2.7 与「人工确认后」指标的关系

| 层 | 何时算 | 用途 |
|---|---|---|
| Proposal（本设计） | extract / link 提案后立即算 | 驱动提取与链接质量 |
| Authority（不在本设计） | confirm / `merge_alias` 后 | 回归「未确认不进 Graph」 |

提案层允许「建议陈默≡陈师傅」；**权威层在确认前必须仍是两个可拒收候选或未合并身份**。

## 3. 技术方案初步设想（设计，非实现）

### 3.1 提案形式：推荐「身份链接提案」为主，`aliases` 为落库投影

**不推荐**在无确认时直接把猜测写进权威 `aliases` 并在 UI 上显示为已成立别名——易被当成事实。

推荐两段式：

1. **LinkProposal（新概念，逻辑对象）**
   - `left_surface` / `right_surface`（或 `left_asset_id` / `right_surface`）
   - `relation`: `same_person_alias`
   - `confidence`: 0–1
   - `evidence_spans[]` + `method`（如 `surname_title_same_scene`）
   - `status`: `proposed`（唯提案）

2. **落库投影（仅在人工接受后）**
   - 接受路径复用现有权威入口：`merge_alias` 或等价 confirm
   - 接受后：保留一个 canonical asset，`aliases` 写入另一表面形式；或按现有 core-asset 命令语义执行
   - **拒绝**则提案关闭，Graph 不变

过渡期可把「尚未确认的提案 aliases」放在只读字段如 `proposed_aliases[]`，与已确认 `aliases[]` 严格分开；若嫌字段膨胀，也可只挂在 revision 级 `identity_link_proposals[]`。**原则：确认前不出现在权威 asset.aliases。**

### 3.2 与人工确认机制的衔接

```text
extract → character candidates (可能仍假分裂)
       → identity link proposals (可追溯)
       → 人工：接受某条 proposal
            → 唯一权威动作：merge_alias / confirm 等价物
            → 之后 #231 归属才能真正用到 aliases
       → 人工：拒绝
            → 提案关闭；保持两候选
```

确定性规则**不得**在 extract 时静默合并两个 asset_id。最多：产出提案，或在 UI 显示「可能是同一人」。

### 3.3 确定性规则：能覆盖到哪里

| 能力带 | 规则直觉 | 置信 | 覆盖用例 |
|---|---|---|---|
| L1 显式 aka | 标签/括注：`周可（外号「阿可」）`、`人物：周可（阿可）` | 高 | A2 |
| L2 姓+职衔同场景 | 已有候选姓 S；同场景出现 `S+师傅/老师/医生/…`；且无第二同姓冲突 | 高 | A1 |
| L3 老S / 小S | 已有候选名含 S 或为 S；同剧本出现 `老S`/`小S`；无同姓冲突 | 中 | A3、部分 A8「浩子」需额外小名规则 |
| L4 截短名 | 较短专名是较长专名的后缀/真子串，且共现 | 低–中 | A4 |
| L5 跨场延迟称呼 | 仅第二场出现「老陈」、第一场「陈默」 | 中（需全剧本索引，仍可确定） | A3 |
| **非确定 / 需模型** | 无共享姓氏的外号（「胖子」↔「陈默」）、纯语境别名、讽刺称呼、代词链、需剧情推理的「陈师傅是在叫别人」 | — | A6 的场外呼喊、A8「妈」、间接提及专项 |

**诚实边界：** 确定性适合「形态可检验 + 同剧本已有锚点专名 + 冲突可检测」。
**需要更强理解（模型提案，仍不自动转权威）的例子：**

- 外号与本名无字形交集（「铁蛋」=「陈默」仅靠前文交代）；
- 讽刺/误称/学舌；
- 代词与「那个人」链；
- 需分辨「陈师傅」是在叫场内陈默还是场外第三人（A6）——规则可用「呼喊不在对话 speaker 位 + 无应答衔接」做**弱抑制**，但不能声称语义理解。

### 3.4 冲突检测（保 FMR 的关键）

在生成 L2/L3 提案前：

- 若剧本中已有 ≥2 个不同候选共享姓 S，则 **禁止** 自动把 `S+职衔` / `老S` 链到其中任意一个（A5）；至多产出「歧义：多名陈*」观察项，置信极低或干脆不提案。
- A6：旁白/远声中的 `陈师傅` 若无对话承接，默认 **不** 链到场内陈默。

### 3.5 与现有代码面的衔接点（仅设计映射）

| 现有 | 设想 |
|---|---|
| `aliases: []` 恒空 | 确认前保持空；提案走 `identity_link_proposals` / `proposed_aliases` |
| `merge_alias` | 继续作为权威合并入口；UI「接受提案」= 调它或薄封装 |
| #231 `_member_spans_in_scene_block` 已读 aliases | 确认后自然生效；**不**让提案层伪写 aliases 来「骗过」归属 |
| `runtime_script_candidate_extraction.py` | 未来 L1–L3 的挂点；本次不实现 |
| week 分支 improved extraction / confirmation | 机制可参考，但产品骨架以 analysis-candidates 为准（矩阵结论） |

### 3.6 本次设计阶段明确不做

- 不调用真实模型，不接 Provider；
- 不写 extract / API / Studio 生产代码；
- 不把代词 coref 并进本指标主集。

## 4. 诚实的边界说明

### 4.1 这套设计能解决多少问题

| 别名现象 | v0.1 评测是否覆盖 | 确定性方案是否可期 |
|---|---|---|
| 姓+职衔，同场、单同姓锚点 | 是（A1） | 是，高置信提案 |
| 标签显式外号 | 是（A2） | 是 |
| 老X / 熟悉后称呼 | 是（A3） | 部分，需冲突检测 |
| 全名↔名截短 | 是（A4） | 弱，易假合并，须保守 |
| 同姓不同人 | 是（A5） | 靠**不链**通过 |
| 职衔呼喊指向场外 | 是（A6） | 部分抑制，非语义理解 |
| week 多角色回归 | 是（A7） | 以不破坏为主 |
| 小名 | 是（A8 部分） | 有限 |
| 亲属称呼当别名 | 刻意弱处理（A8） | **默认不做硬别名** |
| 无字形交集的外号 | 否 | **需模型提案** |
| 代词 / 「那个人」 | 否（另集） | **需模型/指代** |
| 真·长剧本别名漂移 | 否 | 需长文评测集后再说 |

**概括：** 本设计把「可检验的形态别名」收成可回归的提案质量问题，并用反例锁住假合并。它**不能**假装解决叙事级身份理解；那部分应走「受控模型候选 + 同样的人工确认门」，且金标另建。

### 4.2 明确排除

1. 自动合并权威身份 / 静默改写已确认 asset；
2. 用代词链冒充别名指标；
3. 把 ScriptProfile/Beat/间接提及塞进本评测；
4. 在设计阶段调用真实模型生成候选；
5. 以「FSR 降了」为唯一成功标准（必须同时看 FMR / HARD_FAIL）。

### 4.3 建议的实现顺序（供后续任务，非本稿交付）

1. 把 A1–A8 落成机器可读金标（JSON）+ 离线计分脚本（仍可先放 `docs/internal-notes/` 或 `tools/`，属评测 harness）；
2. 在确定性 extract 旁输出 **LinkProposal**（先 L1+L2），接人工接受 → `merge_alias`；
3. 再考虑 L3/L4；L4 默认关闭或极低置信；
4. 模型辅助外号 / 指代作为独立里程碑，复用同一提案与确认门。
