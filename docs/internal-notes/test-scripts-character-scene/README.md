## 01 — 行业标准 · 《最后的光》

- **格式：** `第一场 - 内景 - … - 夜` 式 heading，无 `地点：` / `人物：` 行
- **预期人物：** `玛雅`
- **预期场景：** `废弃灯塔`、`灯塔阳台`（或等价完整地点语义；**不应**是 `颤抖` / `灯上` 碎片）
- **测什么：** 常见行业格式下 Character/Scene 抽取是否可靠；昨天实测场景易 junk

## 02 — 行业标准（更长）· 《海边的信》

- **格式：** 同上，3 场 inline
- **预期人物：** `苏晴`、`老王`、`林悦`
- **预期场景：** `老式邮局`、`海边礁石`、`苏晴的房间`
- **测什么：** 多角色 inline；昨天实测得到 `苏晴没` / `从信封` / `道他可能` 仍 structural PASS —— 应用 candidate-fact 拦住，不能进权威层
- **来源：** 昨天 Codex 提交的 Script Truth `scrrev_9f3d686832b74175` 原文

## 03 — 字段式 · 《归途》

- **格式：** `时间：` / `地点：` / `人物：` 标注
- **预期人物：** `陈浩`、`林秀`
- **预期场景：** `小镇火车站`、`陈浩家中的老屋`
- **测什么：** 字段式路径（昨天实测此格式抽取得较好）；作「格式依赖」对照基线

## 04 — 混合格式 · 《旧照片》

- **格式：** 第一场字段式（`地点：阁楼` / `人物：周明…`）；第二场行业内联（`第二场 - 内景 - 厨房 - 傍晚`）
- **预期人物：** `周明`、`母亲`（第二场仅称谓「母亲」，无全名——可作 display_name 候选，**不要**编造假名）
- **预期场景：** `阁楼`、`厨房`
- **测什么：** 创作者混用两种习惯时，两场人物/地点都应成立，不能只认字段式或只认内联

## 05 — 信息缺失 · 《陌生来电》

- **格式：** 散文式场景，无明确 heading / 地点行 / 姓名
- **预期人物：**
  - 在场角色：**无姓名**（「一个女人」/ 对白头「女人」）→ Character 姓名槽位应为 `missing`（或等价未命名实体 + 姓名 `missing`）
  - 来电者：完全未知 → 也应 `missing`，**禁止**编造号码主人姓名
- **预期场景：** 地点仅「昏暗的房间」级模糊描述 → 地点权威事实应为 `missing`（或极弱 `extracted_from_text` 候选且**不得**自动升权威）；**禁止**编造具体地址/场景名后 PASS
- **测什么：** candidate-fact 的 **`missing` 状态**能否被正确触发；置信度/瞎编不得变成 authoritative

## 使用约定

1. 本目录只放剧本正文 + 本 README；不接生产路径。
2. 后续修提取 / 跑对照时，以本表「预期人物/场景」和状态机草稿为准，而不是以「有没有抽出非空列表」为准。
3. Scene 实体闭环是下一步；今天素材已带场景预期，方便 Character 之后复用同一套剧本。
