## 1. 「间接提及」子类型（不要一锅炖）

当前人物候选来源只有：`人物：`/`角色：` 标签、独立行 speaker cue、bio intro。  
探针「她想起他昨天说起了陈默」→ 0 候选 + `missing_slots`：这是**发现层漏召回**，和「已有人名、场内如何计证据」不是同一题。

| ID | 子类型 | 典型例子 | 有无姓名字符串锚点 | 与相邻问题的边界 |
|---|---|---|---|---|
| **I0** | 纯代词 / 指代链 | 「他走进来」「她没说话」 | 无（封闭词） | **不是**间接提及，也**不是**别名；是 coreference。继续排除（见 §1.1） |
| **I1** | 被提及但未直接出场（有姓名） | 「他昨天说起了**陈默**」；旁白「信是写给**苏晴**的」 | **有**专名表面 | **本议题的核心发现题**：专名只出现在叙事/对白内容里，不是标签也不是 speaker |
| **I2** | 描述性指代（无姓名） | 「那个修钢琴的人」「柜台后的老头」→ 实为已知角色 | **无**可定位专名 | 比 I1 更难；依赖世界知识/前文绑定 |
| **I3** | 「提及」vs「在场」语义（政策题） | 场内出现「说起了陈默」——算不算 `scene_cast` 出演证据？ | 常有姓名 | 与 #231「块内精确字符串命中」重叠：技术上已能命中，**产品语义未定义** |
| **I4** | 开放式「像人名」的散文抓取 | 「苏晴没说话」类动词前缀 | 疑似有 | week/master **故意不做**（会出「苏晴没」假名）；属失败模式，不是目标能力 |

### 1.1 为什么 I0（代词）继续排除

- 别名评测已说明：别名是专名/称呼表面聚类；代词是篇章指代。
- 间接提及若把「他=陈默」并进来，会把评测变成 coref benchmark，指标与失败模式全部换一套。
- 确定性规则对中文代词几乎没有稳定结构信号（不区分性别/角色时更糟）。
- **结论：** I0 单列、本轮不评、不做。

### 1.2 核心到底是哪一类

**工程上最常被叫「间接提及」、且与现状探针对齐的，是 I1：**  
剧本里写了姓名，但抽取通道看不见，系统要么漏人，要么诚实 `missing_slots`（漏召回被装成「没证据」）。

I2 是更难的升级版。I3 是「已经抽到人之后，提及算不算戏份」的政策，不是发现通道。I4 是反模式。

## 2. 各子类型：确定性规则能不能碰

| 子类型 | 有无可靠结构信号？ | 确定性评估 | 主要假阳性 / 风险 |
|---|---|---|---|
| **I0 代词** | 无（需指代消解） | **覆盖不到**；标「需要模型 + 指代专门协议」 | 性别/多人场景乱绑 |
| **I1 有姓名的旁述提及** | 弱：可枚举「说起了/谈到了/想起了/寄给/写给 + X」等，但 X 不保证是人 | **勉强可写脆弱规则，不建议当产品主路径** | 「说起了那天/那封信/老家」；地名/物件专名；与 I4 边界模糊。若改为「仅当 X 已在本剧人名表中」则**不能解决首现于叙事的发现题**（鸡生蛋） |
| **I1 变体：闭集扫描** | 强：已有人名表后，全文/场内精确匹配 | **技术可行，但多半不是「间接提及发现」** | #231 已对场内 display_name/alias 做精确命中；这解决的是**证据附着**，不解决**第一次只在叙事出现** |
| **I2 描述性无姓名** | 无字符串锚点 | **需要模型协助**；规则几乎不可做 | 「修钢琴的人」可能多人；易脑补 |
| **I3 提及≠在场** | 有字符串即可命中（现状） | **不缺规则，缺产品定义** | 若把「说起了X」当 cast，会与缺失证据备忘里「有名无戏份」冲突：叙事提及会被当成戏份 |
| **I4 散文开放 NER** | 有（动词前缀等）但**已被否定** | **明确不做** | 已验证假名灾难 |

### 2.1 难在哪里（精确定位）

1. **发现 vs 证据附着混谈**  
   - 发现：姓名从未进候选表（探针）。  
   - 附着：姓名已在表中，场内叙事再出现 → #231 已能打 span。  
   只做闭集扫描会看起来「做了间接提及」，实际**没堵住探针那种洞**。

2. **开放发现与 fail-closed 纪律冲突**  
   week hard rule：禁止动词前缀抓名、禁止剧情推断 Profile/Beat、cast 不用散文 alone。  
   任何「从散文新发现人名」的确定性方案，都在重新打开这条纪律；要用极窄句式白名单，评测集会逼着加规则 → 过拟合，且仍挡不住语义假阳性。

3. **I3 政策未定会污染缺失证据评测**  
   刚冻结的缺失范围依赖「块内无精确命中 → missing」。若间接提及项目把叙事提及一律当 cast 证据，M1「有名无戏份」真值会被改写。两件事必须先定政策，不能并行瞎做。

4. **缺整条抽取通道是真的**  
   不是少写几条 regex，而是：**没有**与标签/speaker 同级的、已验收的「叙事提及 → 人物候选」通道；矩阵也把「受控模型候选」放在 deterministic 之后。

## 3. 最终判断：现在适合做吗？

### 判断：**现在不适合**按别名 / 缺失证据同规格（评测协议 → 确定性实现 → 计分）开工。

这不是「找不到小角落」的推脱，而是投入产出与风险不对称：

| 若强行最小子集 | 实际得到什么 | 为什么不够格当「下一个复杂场景交付」 |
|---|---|---|
| 只做闭集人名场内扫描 | 多半与 #231 重复 | 不回答探针漏召回 |
| 只做「说起了X」白名单发现 | 脆弱、易假阳性、易过拟合金标 | 违反当前 fail-closed 主路径；无模型时难守 FMR 式纪律 |
| 只写 I3 政策备忘 | 有价值，但是**产品语义**，不是理解能力增量 | 可单开小讨论，不应冒充间接提及主线完成 |
| 上模型做 I1/I2 | 才对齐问题本质 | **受控模型候选接口尚未成为本阶段可依赖的交付面** |

### 什么条件下值得重新考虑

同时满足再开（建议）：

1. **受控模型候选**可对 revision 产出「可追溯、低置信、须人工确认」的人物提案（矩阵已规划的方向），且**默认不进 Graph**；  
2. **I3 政策写清**：叙事提及 / 对白提及 / 舞台指示中的姓名，分别是否计入 `scene_cast` 证据（与缺失证据 M1 对齐）；  
3. 评测集能分开度量：**发现召回（I1）**、**描述指代（I2）**、**错误把提及当在场（I3）**，并有类似别名的硬反例（地名、物件、假名）；  
4. 确定性主路径保持现状（标签/speaker/bio），**模型提案是旁路**，不靠加散文 NER 抢召回。

在此之前：间接提及记为 **已知缺口 + 暂缓**；优先完成已开的别名提案工程化判断，以及缺失证据（槽级 + 关系级）评测落地。

### 若必须留一句「最小起点」

唯一诚实的、可现在做且不假装解决 I1 的，只有：

> **产品备忘：I3「提及 vs 在场」是否算 ownership 证据** —— 纯语义冻结，不改抽取、不开评测集。

这**不够**称为「间接提及场景启动」；本报告不把它升格为推荐下一步主线。

## 4. 一句话归档

**间接提及应拆成 I0–I4；核心洞在 I1（有姓名的叙事发现），确定性没有安全主路径；I2 需模型；I3 是政策；I4 禁止。当前应暂缓实现与正式评测协议，条件是受控模型旁路 + I3 与缺失证据对齐后再开。**
