# 「有人但叫不出名字」产品价值与边界评估（2026-08-05）

| 项 | 值 |
|---|---|
| 状态 | **结论：当前不值得实现**（技术空洞 ≠ 产品缺口） |
| 范围 | Script Core / analysis-candidates 人物资产；对照缺失证据备忘 §2.3 |
| 动作 | 只评估，不改 schema、不加开关、不写生产实现 |

---

## 1. 问题到底在问什么

表面症状：`CandidateCharacter.evidence_spans` 有 `min_length=1`，且 `display_name` 也有 `min_length=1`。系统无法表示：

> 「这里确认有一个人物实体，但我们没有可用的专名。」

于是表面上只剩两种粗路径：

1. 编一个名字当候选（违反 fail-closed）；或  
2. 不产出人物候选 → 若全剧无专名，则 `missing_slots` 含 `named_characters`（「假装没有可追踪的命名人物」）。

需要拆开的是：**「没有可追踪命名人物」是不是错误？** 还是对当前下游来说正是正确语义？

---

## 2. 真实边界：哪些剧本片段会碰到

### 2.1 会触发讨论的片段类型

| 类型 | 例子 | 现有确定性行为 | 是否「匿名实体」题 |
|---|---|---|---|
| A. 纯泛称出场 | 「一个陌生人推门进来，什么也没说就走了」 | `_GENERIC_PEOPLE` 拒绝；无专名则槽级 missing | 是本题核心例子 |
| B. 泛称 speaker | 独立行 `女人` / `来电者` | 同样拒绝 | 是 |
| C. 关系描述无专名 | 「陈默的朋友站在门口」（无林悦） | 不建新人物；也不把「朋友」当 display_name | **边界**——更像描述指代 / I2，不是「已确认要追踪的匿名 ID」 |
| D. 有专名的关系 | 「她的朋友林悦」 | bio/标签可出林悦 | 否（有名） |
| E. 气氛群众 | 「街上路人匆匆走过」 | 不建资产 | 通常否——气氛，不是身份资产 |

### 2.2 与「间接提及」的严格区分

| | 匿名存在（本题） | 间接提及（I1/I2，已判暂缓） |
|---|---|---|
| 有无专名字符串 | **无**可用专名 | I1 **有**专名（「说起了陈默」）；I2 无专名但是描述指代已知人 |
| 目标 | 要不要新建「未命名人物实体」 | 要不要发现/附着已有或新的**命名**候选 |
| 失败形态 | 编名 vs 不建实体 | 漏召回命名人 / 假 NER |
| 结论关系 | **不是同一题**；不要用匿名实体去「补」间接提及 |

「陈默的朋友」若下游需要的是「多一个可出图角色」，本质仍是：**要么后来出现专名，要么人工 `create`/`edit` 起名**——不是 schema 允许空 `display_name` 就能自动变好。

## 3. 下游到底要不要「匿名但确认存在」的人物资产

对照当前 master 的真实消费者（非假想）：

| 下游 | 对人物的假设 | 对匿名实体的态度 |
|---|---|---|
| Script Core asset / Graph 节点 | `display_name` 为身份键；`asset_id` 由 type+label+证据摘要派生 | 无稳定标签则无稳定身份 |
| `scene_cast` ownership | 用 display_name / aliases 做块内精确命中 | 匿名无法做「精确名命中」政策；关系会退化成噪声或永远 missing |
| Dynamic production plan | `character_refs` 必须指向 Character truth | 需要可引用的命名资产 |
| Image admission / 提示词 | 用 `display_name`、视觉身份文案 | 已有「待确认资产」兜底文案，但仍是**有条目的资产**，不是「空名实体」 |
| M6 script plan / Codex planner | `requires_named_characters: True`；测试明确禁止乱加「路人」当角色名 | **主动排斥**泛称入角色表 |
| 分镜描述 | `atmosphere` / description 散文可写「陌生人」 | **气氛层**已能承载，不必升格为 Script Core 人物 |

**产品判断：**  
当前纵切要的是 **可复用、可确认、可出图/可挂镜头的命名身份**。  
「确认存在但无专名」的路人/陌生人，在制作上更接近 **气氛 / extras 描述**，而不是 Asset Bible 里的一等人物资产。

因此：`missing_slots: named_characters` 在「全是泛称」剧本上的含义，应读作：

> 「没有可供生产链路追踪的命名人物」  

而不是：

> 「系统撒谎说现场没有人类躯体」。

后者若要表达，应在镜头/场面描述或将来单独的 `extra`/`atmosphere_agent` 模型里做，而不是硬塞进 `CandidateCharacter`。

---

## 4. 若强行改 schema，风险是否被低估

即便只做「受开关保护的最小版」，也会碰到：

1. **不只是 `evidence_spans.min_length`**  
   - `display_name: min_length=1` 同样硬；空名或占位名（「未命名人物#1」）会立刻变成**编造标签**，与「不编名字」纪律冲突。  
2. **身份与幂等**  
   - `asset_id` / preservation key 依赖 label；多个「陌生人」如何去重、跨 revision 如何保留，没有现成答案。  
3. **ownership**  
   - 精确名命中政策无法服务匿名实体；要么放宽成弱匹配（假阳性），要么关系永远 missing（无确认价值）。  
4. **确认语义**  
   - 人工确认「确实有这个人但没名字」——Graph 节点标签是什么？后续 merge 成真名如何溯源？等同再设计一套「占位→命名」状态机。  
5. **契约面**  
   - OpenAPI、Studio 审阅列表、merge_alias、图片准入、计划 `character_refs` 都默认「有名」。开关默认关也挡不住半接入时的 UI/测试分叉成本。

**风险结论：** 相对产品收益，契约与状态机成本偏高；不是「改一个 Field 约束」能收尾。

---

## 5. 最终判断

### 不值得在本阶段实现「匿名人物候选」

理由（非空话）：

1. **下游没有在要这种一等实体**——要的是命名可追踪资产；气氛陌生人已有散文/镜头描述通道。  
2. **现有 fail-closed（拒泛称 + 槽级 missing）对齐当前产品语义**，评测 M2 也按此验收；把它改成「匿名候选」是改产品定义，不是补洞。  
3. **与间接提及不同题**；用匿名实体去填「叫不出名」会制造 Asset Bible 噪声，并与「禁止路人角色名」方向相反。  
4. **真要做，也是新产品类型**（extras / 未命名出场计数），应另开范围，而不是放松 `CandidateCharacter` 的命名+证据约束。

### 什么条件下值得重新考虑

同时满足再开设计（仍建议独立 memo，不偷改 min_length）：

- 明确下游（例如群演调度、出入镜人数门禁）**书面要求**「可确认、可计数、可暂无名」的实体；  
- 与命名 Character **分型**（不要共用 `display_name` 身份键）；  
- 确认路径只确认「存在/场次」，命名升级走单独命令；  
- 与 I2 描述指代、气氛描写的边界写进契约测试。

在此之前：保持现状；技术空洞记在缺失证据备忘 §2.3 / §5.1，**标记为「已知、低优先、非当前缺口」**。
