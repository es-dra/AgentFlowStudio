## 诚实评估

**解决了什么**

- 发现层过拟合：换左上下文后的沈岚/江澄 **能找回**
- 把「是不是人名/是不是在场」交给 LLM 后，对白/业务噪声过滤在本轮 **没有** 出现「把整句对白判 true」的新事故

**没解决 / 新边界**

1. **`is_character` 语义**：宽召回找回的 I1 人名，在现行规则下几乎全是 false。若目标是「记入人物候选表」，需要单独字段（例如 `is_person_mention` vs `is_onstage_character`），不能指望现在的 true/false 一锅端。
2. **开放无引号 NER 仍不敢开**：结构宽召回目前主要靠引号 + 少量 cue；纯散文无引号首现姓名仍可能漏（本批金标碰巧都有引号或「提到了」）。
3. **成本**：调用量随引号密度线性涨；生产路径必须限流/缓存/只对 revision 异步跑。
4. **长引号**：放宽到 24 字后会收进整句（「钥匙在三零二的钟里。」），靠 LLM 挡——本轮挡住了，但不保证永远稳。

**结论**：这个方向**对「发现过拟合」是对症的**；代价是更多 LLM 调用。判断器在本轮噪声上表现稳定。下一步若继续，应先厘清「间接提及人名」要进哪一种候选槽，而不是继续拧发现白名单。
